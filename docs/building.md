# Building

A local development build on a real device, without EAS. Every step
cites the official Expo or Apple page it comes from; nothing here goes
beyond those pages. Expo documentation checked is SDK 58.

All commands run from `apps/mobile`. The app identifier
`com.maxirebolo.beatly` is set in `apps/mobile/app.config.ts` for both
`ios.bundleIdentifier` and `android.package`; each "needs to be unique"
on its store ([app config](https://docs.expo.dev/versions/latest/config/app/)).

`ios/` and `android/` are generated by the build and stay ignored and
unversioned.

`expo-dev-client` is not installed. The Expo environment guides below
install it as one of their steps; this repo builds without it, and adding
it is a separate issue. The
[local app development page](https://docs.expo.dev/guides/local-app-development/)
does not require it.

## Commands

`npx expo run:ios` and `npx expo run:android` compile and install the
native binary, then start Metro. The `--device` flag selects a device to
run on. If `ios/` or `android/` do not exist yet, they first run
`npx expo prebuild` to generate them
([local app development](https://docs.expo.dev/guides/local-app-development/)).

## iOS on a physical iPhone

Source for the setup:
[Expo environment guide, iOS physical device, local build](https://docs.expo.dev/get-started/set-up-your-environment/?platform=ios&device=physical&mode=development-build&buildEnv=local).

1. Install Xcode from the Mac App Store. In the Xcode settings, choose the
   most recent version in the Command Line Tools dropdown.
2. Connect the iPhone to the Mac with a USB cable. Unlock it and tap Trust
   if prompted (same guide).
3. Enable Developer Mode on the iPhone. It "only appears in Settings if you
   initiate pairing or if you previously paired the device to a Mac". In
   Privacy & Security, turn on the Developer Mode switch under Security and
   tap Restart in the alert. After the restart, swipe up, tap Enable in the
   dialog and enter the device passcode
   ([Apple](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)).
4. Generate the native project: run `npx expo prebuild`, so that `ios/` exists
   before the next step ([local app development](https://docs.expo.dev/guides/local-app-development/)).
5. Choose the signing team. Open the iOS workspace with `xed ios`; under
   Signing > Team choose your team
   ([Expo](https://docs.expo.dev/submit/ios-manual/)). In the project editor,
   select the Signing & Capabilities pane and choose a team from the Team
   pop-up menu
   ([Apple](https://developer.apple.com/documentation/xcode/preparing-your-app-for-distribution)).
   Without a developer program membership, Xcode shows the account as a
   Personal Team
   ([Apple](https://developer.apple.com/help/account/basics/about-your-developer-account)).
   With a unique `ios.bundleIdentifier`, "Xcode generates the provisioning
   profile for the app signing step" (Expo iOS guide above).
6. Run `npx expo run:ios --device` and select the iPhone from the list. It
   runs a dev server after building (Expo iOS guide above).

### Free Apple Account limits

Without a developer program membership you can register up to 10 App IDs
and up to 3 devices, both expiring after 7 days, and install up to 3 apps
per device. Provisioning profiles expire 7 days after issuance, so the app
must be rebuilt and reinstalled after expiration
([Apple](https://developer.apple.com/help/account/basics/about-your-developer-account)).

### Trusting the developer certificate

Not documented here on purpose. Apple documents the trust flow (Settings >
General > VPN & Device Management, then the developer, then Trust) only for
enterprise apps
([Apple](https://support.apple.com/en-us/118254)). Neither Apple nor Expo
documents it for an app signed with a Personal Team, so this guide does not
list it as a step.

## Android on a physical device

Source for the setup:
[Expo environment guide, Android physical device, local build](https://docs.expo.dev/get-started/set-up-your-environment/?platform=android&device=physical&mode=development-build&buildEnv=local).

1. Install JDK 17. On macOS: `brew install --cask zulu@17`, and set
   `JAVA_HOME=/Library/Java/JavaVirtualMachines/zulu-17.jdk/Contents/Home`.
2. In Android Studio, Settings > Languages & Frameworks > Android SDK,
   install "Android SDK Platform 36" and "Sources for Android 36". Under SDK
   Tools, install Android SDK Build-Tools.
3. Set `ANDROID_HOME=$HOME/Library/Android/sdk` and add
   `$ANDROID_HOME/emulator` and `$ANDROID_HOME/platform-tools` to `PATH`.
4. Enable USB debugging: Settings > About phone > Software information, tap
   "Build number" seven times; then Settings > Developer options > enable
   "USB debugging".
5. Plug the phone in via USB. `adb devices` must list it with "device".
6. Run `npx expo run:android --device`. The environment guide shows
   `npx expo run:android`; `--device` comes from
   [local app development](https://docs.expo.dev/guides/local-app-development/).

## When to rebuild

`pnpm dev` (Metro) reloads JavaScript only and never applies a native change.
The native binary must be built again after `pnpm install` brings a change to
`patches/expo-audio@58.0.10.patch`, after an expo-audio upgrade, or after a
change to the `plugins` of `app.config.ts`. Run `npx expo prebuild --clean`
(regenerates `ios/` and `android/`, needed for a plugin change; see
[Expo prebuild](https://docs.expo.dev/workflow/prebuild/)) and then
`npx expo run:ios --device` or `npx expo run:android --device`. After `--clean`,
repeat the signing team step on iOS.
